## 1. Introduction

This system automates attendance marking from **photographed signing sheets**. Admin staff
photograph a printed signing sheet (fixed, static layout) where students have signed using
different-colour pens, and also provide a data file (`info.xml`) containing student index
numbers, names, and subject information. A **reference signature database** is provided for
identity verification.

The program processes each photograph through an image-processing pipeline, detects whether
each student has signed, **verifies the signature against the stored reference** to confirm
the sign belongs to the correct student, marks the student **Present** or **Absent**, stores
the result in a local database, and visualizes attendance summaries as graphs.

---

## 2. System Objectives

| # | Objective |
|---|-----------|
| O1 | Accept a photographed signing-sheet image as input |
| O2 | Remove noise / unwanted data and correct geometric distortion (rotation, scale) |
| O3 | Segment the sheet into rows and locate each student's signature cell |
| O4 | Detect whether a signature is present in each cell |
| O5 | **Verify** the detected signature against the reference signature DB for that student |
| O6 | Mark attendance as *Present* / *Absent* (and flag verification failures) |
| O7 | Store attendance in a local database |
| O8 | Display attendance summaries per student as graphs |

## 3. High-Level Architecture

The system follows a **layered architecture**. Core logic lives in reusable modules; the
Streamlit UI and the command-line scripts are thin layers on top of the same core.

└───────────────┬─────────────────────────────┬────────────────┘
                │                             │
┌───────────────▼─────────────────────────────▼────────────────┐

│  └────────────┘ └────────────┘ └────────────┘ └────────────┘ │
│         │              │              │              │        │
│  ┌──────▼──────┐ ┌─────▼──────┐ ┌─────▼──────┐ ┌─────▼──────┐│
│  │ info.xml    │ │ Visualiza- │ │  Database  │ │  Reporting ││
│  │  Parser     │ │   tion     │ │   Access   │ │  / Testing ││

`python sams.py <image> <info.xml>` and the Streamlit buttons run the exact same pipeline.

### 4.1 Detailed Feature Breakdown (per member)

Each member owns one feature end-to-end. The breakdown below lists **what to build**, the
**techniques/libraries** to use, the **files owned**, the **input → output** of that feature,
and the **individual-contribution focus** for the 2-page write-up.

---

**F1 · Image Acquisition & Pre-processing** — *Member 1*
- **Task:** Read the photo and prepare a clean single-channel image: convert to greyscale, then smooth to remove camera grain / paper texture / unwanted noise.
- **Techniques:** `cv2.imread`, `cv2.cvtColor` (BGR→Gray), `cv2.GaussianBlur` / `cv2.medianBlur`.
- **Course link:** L2 (digital image fundamentals), L3.2 (image filtering).
- **Files:** `src/image_processing.py`
- **Input → Output:** raw colour photo → denoised greyscale image.
- **Write-up focus:** why greyscale, blur kernel choice, noise types handled.

---

**F2 · Geometric Correction** — *Member 2*
- **Task:** Fix the tilted phone photo — detect skew angle and rotate to align the grid, then scale/resize to a standard size so all sheets share the same coordinate system.
- **Techniques:** `cv2.getRotationMatrix2D`, `cv2.warpAffine`, `cv2.resize`; skew detection via Hough lines or minAreaRect.
- **Course link:** L12.1 (2D transformations), L6.3/L7.1 (Hough transform for line/skew).
- **Files:** `src/transforms.py`
- **Input → Output:** denoised image → deskewed, normalized-size image.
- **Write-up focus:** rotation & scaling matrices, deskew angle estimation.

---

**F3 · Table & Cell Segmentation** — *Member 3*
- **Task:** Detect the table grid (horizontal + vertical lines) and extract each student's row, then isolate the signature-column cell for every row, in order.
- **Techniques:** binarization (`adaptiveThreshold`/Otsu), morphology (`morphologyEx` dilate/erode) to isolate grid lines, contour/bounding-box detection.
- **Course link:** L4.3 (dilation & erosion), L6 (segmentation).
- **Files:** `src/table_extraction.py`
- **Input → Output:** normalized image → ordered list of signature-cell crops.
- **Write-up focus:** grid-line extraction, cell ordering, morphology kernels.

---

**F4 · Signature Detection** — *Member 4*
- **Task:** For each signature cell, decide present vs empty by measuring ink content.
- **Techniques:** count non-white (ink) pixels vs a threshold; connected-components to ignore stray specks.
- **Course link:** L7.3 (edge detection can strengthen strokes), L2.
- **Files:** `src/signature_detection.py`
- **Input → Output:** cell crop → boolean signed / not-signed.
- **Write-up focus:** ink-threshold tuning, false-positive handling (smudges).

---

**F5 · Signature Verification** — *Member 5*
- **Task:** Confirm the signature actually belongs to that student by matching it against the reference signature in the given DB; produce a similarity score.
- **Techniques:** ORB/SIFT feature matching, or `cv2.matchTemplate`, or SSIM; normalize both images before comparison.
- **Course link:** L7.3 (features/edges), general image processing.
- **Files:** `src/signature_recognition.py`
- **Input → Output:** detected signature + reference → similarity score + match Y/N.
- **Write-up focus:** matching algorithm choice, score threshold, proxy detection.

---

**F6 · Attendance & Database** — *Member 6*
- **Task:** Parse `info.xml`, map detection/verification results to the correct student (by row order), and store/query attendance in SQLite (also holds reference-signature records).
- **Techniques:** `xml.etree.ElementTree`, `sqlite3` (CRUD), schema design with UNIQUE + FOREIGN KEY.
- **Course link:** data handling / integration.
- **Files:** `src/info_parser.py`, `src/database.py`
- **Input → Output:** results + info.xml → persisted attendance records.
- **Write-up focus:** XML mapping, DB schema, present/absent/flagged storage.

---

**F7 · Data Visualization** — *Member 7*
- **Task:** Show an attendance summary for a given student as a suitable graph (bar/pie/timeline across the 5 sheets).
- **Techniques:** `matplotlib` (bar, pie, line), query DB per student index.
- **Course link:** L8.3 (data visualization).
- **Files:** `src/visualization.py`, `infovis.py`
- **Input → Output:** student index → attendance chart figure.
- **Write-up focus:** chart selection, what each graph communicates.

---

**F8 · System Integration & UI** — *Member 8*
- **Task:** Build the Streamlit app that ties everything together (upload → process → results → save → visualize → verify), plus testing and report assembly.
- **Techniques:** `streamlit` (`file_uploader`, `image`, `pyplot`, buttons), integration testing.
- **Course link:** integration of all modules.
- **Files:** `app.py`, `tests/test_pipeline.py`, report coordination.
- **Input → Output:** all modules → one working, demonstrable application.
- **Write-up focus:** UI design, wiring the pipeline, testing across all 5 sheets.

## 5. Image Processing Pipeline (All Steps)

The input is a smartphone photo — tilted, uneven lighting, background clutter, coloured ink.
The pipeline transforms it into clean, aligned, binary signature cells. **Every stage is saved
as an image** to `output/processed/` for report screenshots.

```
 INPUT PHOTO
     │
 ┌───▼───────────────┐  Step 1: LOAD
 │ cv2.imread()      │  Read the raw colour image (BGR).
 └───┬───────────────┘
     │
 ┌───▼───────────────┐  Step 2: GREYSCALE
 │ BGR → Gray        │  Colour is irrelevant for shape; reduces 3 channels to 1.
 └───┬───────────────┘  cv2.cvtColor(img, COLOR_BGR2GRAY)
     │
 ┌───▼───────────────┐  Step 3: SMOOTHING / NOISE REMOVAL
 │ Gaussian / Median │  Remove camera grain, paper texture, "unwanted data".
 │ blur              │  cv2.GaussianBlur() or cv2.medianBlur()
 └───┬───────────────┘
     │
 ┌───▼───────────────┐  Step 4: ROTATION (DESKEW)
 │ 2D rotation       │  Phone photos are tilted. Detect skew angle and rotate
 │ transform         │  the sheet so rows/columns are axis-aligned.
 └───┬───────────────┘  cv2.getRotationMatrix2D() + cv2.warpAffine()
     │
 ┌───▼───────────────┐  Step 5: SCALING / NORMALIZE
 │ resize to a       │  Bring every sheet to a standard size so cell coordinates
 │ standard size     │  are consistent across all 5 test sheets.
 └───┬───────────────┘  cv2.resize()
     │
 ┌───▼───────────────┐  Step 6: BINARIZATION (THRESHOLD)
 │ adaptive / Otsu   │  Convert to pure black-and-white: ink = black, paper = white.
 │ threshold         │  cv2.adaptiveThreshold() / cv2.threshold(..., THRESH_OTSU)
 └───┬───────────────┘
     │
 ┌───▼───────────────┐  Step 7: MORPHOLOGY (CLEAN-UP)
 │ dilation /        │  Close small gaps, strengthen grid lines, remove specks.
 │ erosion           │  cv2.morphologyEx() (L4.3 Dilation & Erosion)
 └───┬───────────────┘
     │
 ┌───▼───────────────┐  Step 8: TABLE / CELL EXTRACTION
 │ detect grid lines │  Find horizontal + vertical lines → locate each row and the
 │ → per-row cells   │  signature column cell for every student (in order).
 └───┬───────────────┘
     │
 ┌───▼───────────────┐  Step 9: SIGNATURE REGION EXTRACTION
 │ crop signature    │  Crop the signature cell for each student → feed to detection
 │ cells             │  and verification.
 └───────────────────┘
```

> **Course tie-in:** Steps 4–5 (rotation, scaling) are **2D geometric transformations**
> (L12.1). Step 3 is **image filtering** (L3.2). Step 7 is **morphology** (L4.3). Documenting
> these mappings in the report earns marks for "image processing techniques used".

## 6. Signature Verification Sub-system (Feature F5)

A reference signature database is **given** (student index → name → reference signature
image). Verification answers: *does the signature in this cell actually belong to this
student?* — catching proxy signing / mismatches.

**Process:**
1. Extract the signature region from the cell (Step 9 above).
2. Pre-process it identically to the reference (greyscale, threshold, resize to a fixed box).
3. Compare against the stored reference(s) for that student index using one of:
   - **Feature matching** — ORB / SIFT keypoints + descriptor matching (robust, recommended).
   - **Template matching** — `cv2.matchTemplate` (simpler, less robust to rotation/scale).
   - **Structural similarity** — SSIM score between normalized images.
4. Produce a **similarity score**. If score ≥ threshold → *verified match*; else → *mismatch*.

```
 detected signature ─┐
                     ├─► pre-process ─► compare (ORB/SIFT) ─► similarity score ─► match? Y/N
 reference (from DB) ─┘
```

## 7. Attendance Decision Logic

Detection (F4) and verification (F5) combine into the final status:

| Signature in cell? | Matches reference? | Final Status |
|--------------------|--------------------|--------------|
| No | — | **Absent** |
| Yes | Yes | **Present (Verified)** |
| Yes | No | **Present — flagged** (verification failed / possible proxy) |

The status, together with the mapped student (from `info.xml`, by row order), the subject
code and the date, is written to the database.

## 8. Database Design

Two logical tables in the local SQLite database (`output/attendance.db`).

**Reference signatures (given):**
```sql
CREATE TABLE IF NOT EXISTS students (
    student_idx   TEXT PRIMARY KEY,   -- e.g. 10000409
    name          TEXT NOT NULL,
    signature_ref BLOB               -- reference signature image bytes (or file path)
);
```

**Attendance (produced by the system):**
```sql
CREATE TABLE IF NOT EXISTS attendance (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    student_idx   TEXT NOT NULL,
    subject_code  TEXT,
    date          TEXT,
    status        TEXT CHECK(status IN ('present','absent','flagged')),
    match_score   REAL,               -- verification similarity score
    UNIQUE(student_idx, subject_code, date),
    FOREIGN KEY (student_idx) REFERENCES students(student_idx)
);
```

## 9. Data Visualization (Feature F7)

The visualization program shows a summary of attendance for a **given student**, using a
suitable graph (per the data-visualization knowledge from L8.3).

```
$ python infovis.py 10000409
```

Suggested charts:
- **Attendance % over dates** — line or bar chart across the 5 signing sheets.
- **Present vs Absent** — pie / donut chart of the student's overall record.
- **Per-session status** — colour-coded timeline (green = present, red = absent, amber = flagged).

In the Streamlit UI, the user enters a student index and the corresponding chart renders via
`st.pyplot`.
